01 · 问题

市场想要真实的价格，但每个人都想藏住自己的底牌

买方 agent 知道自己的支付意愿 v，卖方 agent 知道自己的成本 c —— 两边都不想让对方看见。 靠来回砍价，就是一场低效的猜谜：藏数字、试探、虚张声势。价格信号因此失真。

机制设计的解法不是「劝大家诚实」，而是改变规则本身： 定一套报价与结算的规则，让「如实上报」恰好成为每个人的最优选择 —— 哪怕他满脑子想的都是怎么占便宜。

这套机制需要同时满足三个条件：

DSIC 占优策略激励相容 —— 无论别人怎么报，如实报价都是你的最优策略。
这是全套性质里最难满足、也最值钱的一条。
IR 个体理性 —— 自愿参与，成交的买方付款不超过自己的估值，卖方收款不低于自己的成本，没人被迫做亏本生意。
BB 强预算平衡 —— 买方总付款 ≥ 卖方总收款。平台是「交易所 + 清算所」，不靠补贴运转、也不需要另找钱填窟窿。
议价 = 猜谜 · 出清 = 报价
两种世界的区别：上边靠猜别人，下边只用管好自己的数字 —— 机制接手了「防欺骗」的工作。
!

但有一个理论上的天花板：Myerson–Satterthwaite 定理（1983）证明，当买卖双方都有私人信息时， 「占优策略真话 + 个体理性 + 预算平衡 + 完全效率」四者不可兼得。 唯一能让步的是效率 —— 本机制选择牺牲至多一笔边际交易，其余三条全部保住。

怎么读这张图

红色阶梯是买方报价的降序排列（需求）， 蓝色阶梯是卖方要价的升序排列（供给）。 第 i 个单位的买方出价 v(i) 与卖方要价 c(i) 一对一对齐比较， v(i) ≥ c(i) 能成立的最大 i 就是 k* —— 完全效率下能成交的笔数。

图右侧灰色的「第一对被排除的报价」v(k*+1)、c(k*+1) 是定价的钥匙： 它们的中间价 p0 = (v(k*+1) + c(k*+1)) / 2 若恰好落在 [c(k*), v(k*)] 区间内，则 k* 笔全部按 p0 统一成交（分支 a）。

若 p0 越界、或第 k*+1 位根本不存在，则退回 分支 b：牺牲第 k* 笔，用被牺牲者的报价定价 —— 买方付 v(k*)、卖方收 c(k*)，两者之差归平台。

为什么「牺牲一笔」是必须的

DSIC 的要害是「没有任何人的成交价依赖于他自己的报价」。 分支 a 里，价格 p0 由第 k*+1 名决定 —— 那是没能成交的人，成交者无法通过报价影响它。

而当第 k*+1 名不存在时（比如买方刚好只有 k* 个），若硬用「人工上下界」补位算 p0， 成交者的报价就会溜进定价公式 —— DSIC 应声碎裂。 正确做法是退回分支 b：连定价用的 v(k*) 和 c(k*) 也属于被牺牲的边际交易者， 与成交者无关。

这就是 Myerson–Satterthwaite 定理要求的代价：至多牺牲一笔交易。 市场越厚，这一笔越无关紧要 —— 代价有上界，收益（诚实的价格信号）却是全场的。

05 · 系统

从机制到服务：六个组件、十个端点

Node 22 + TypeScript（原生类型剥离，零构建）+ node:http（零第三方依赖）。 单进程内存存储，为 MVP 刻意保持轻量。

引擎不暴露任何单个 agent 的报价；`GET /rounds/:id/result` 按调用者角色裁剪 —— 你只能看到「自己是否成交、成交价多少」，看不到别人的数字。

十分钟上手：一轮完整交易的 curl 流程

# 启动（需要 Node ≥ 22.6，零依赖） $ node src/index.ts # -> http://127.0.0.1:8787 # 1. 注册：1 个买方 + 1 个卖方 $ curl -s -X POST localhost:8787/agents \ -d '{"role":"buyer","name":"alpha"}' # -> { "agentId": "ag_...", "apiKey": "sk_..." } # 2. 开市：创建轮次 $ curl -s -X POST localhost:8787/rounds \ -d '{"roundId":"r-001"}' # 3. 报价（买方报出价 / 卖方报要价） $ curl -s -X POST localhost:8787/rounds/r-001/bids \ -H "X-API-Key: sk_..." -d '{"value":42,"quantity":1}' $ curl -s -X POST localhost:8787/rounds/r-001/asks \ -H "X-API-Key: sk_..." -d '{"cost":30,"quantity":1}' # 4. 出清 + 查结果 + 行情 $ curl -s -X POST localhost:8787/rounds/r-001/clear $ curl -s localhost:8787/rounds/r-001/result -H "X-API-Key: sk_..." $ curl -s localhost:8787/market-data
错误统一为 { error: { code, message } } + 明确的 HTTP 状态码（401/403/404/409/400）。

三条设计红线：① 他人报价绝不披露，只公开聚合数据； ② 声誉只作信号，绝不进入定价公式（一旦进入，操纵声誉就能获利，DSIC 立碎）； ③ 周期性出清，不做连续撮合（连续撮合不具占优策略真话性质）。
06 · 工程发现

一个差点写错的边界：两种「McAfee」并不等价

查证 McAfee (1992) 时会遇到两种流传较广的边界处理写法。它们看着只差一行代码， 但其中一种会悄悄破坏 DSIC。这是本项目通过穷举对照亲手实锤的发现。

差别在哪一行？

变体 A：当第 k*+1 位不存在时，用「人工上下界」（买方补 0、卖方补 1）凑一个 p0 照常定价。
变体 B：分支 a 必须满足「至少 k*+1 个买方且 k*+1 个卖方」；缺位则退回分支 b，牺牲边际交易。

穷举对照（各 20,900 次检验）：变体 A 出现 42 个反例， 变体 B 0 违反。反例长这样：

市场：买方 [3, 4]、卖方 [1]。
真值 3 的买方如实报 3 → 排序在 4 之后，拿不到唯一席位 → 效用 0
改口虚报 4 → 并列第一、借补位定价成交 → 效用 +0.5

诚实反而更差 —— DSIC 就是这样被一行「补位」悄悄破坏的。 本实现采用变体 B。
