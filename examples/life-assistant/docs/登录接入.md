# 微信与支付宝登录接入

后端已实现真实 OAuth 授权码交换和头像读取接口。当前项目没有真实应用配置，也没有公网回调站点或真实账号联调结果；`GET /api/auth/providers` 会如实返回 `enabled: false` 和缺少配置的原因。模拟测试通过不代表平台审核、授权或真实登录已完成。

## 接口与前端流程

1. `GET /api/auth/providers` 返回 `{ok, providers:[{id,name,enabled,reason,verification}], oauth_verified:false}`。`id` 为 `wechat` 或 `alipay`。配置完整后，只有通过与回调相同的 HTTPS 站点访问时才会启用；`verification` 仍标为 `not_verified`，因为代码不能替代真实账号验收。
2. `GET /api/auth/me` 返回 `{ok, authenticated, profile}`。未登录时 `profile` 为 `null`；登录后仅返回 `{name, avatar, provider}`，分别来自平台昵称、头像与登录来源。前端应通过 `textContent` 显示昵称，并把头像作为图片 URL 使用。
3. `POST /api/auth/start`，JSON 请求 `{provider:"wechat"}` 或 `{provider:"alipay"}`。成功返回 `{ok:true,url,expires_in:600}` 并设置浏览器绑定 Cookie；前端用顶层页面导航跳转 `url`，不要在后台直接调用授权地址。
4. 平台跳转到 `GET /auth/callback/wechat` 或 `GET /auth/callback/alipay`。服务端检查一次性 state、有效期及浏览器 Cookie，交换授权码并读取资料；成功设置会话 Cookie 后 `302 /?login=success`，失败只 `302 /?login=failed`，不把授权码、令牌或平台错误原文放进地址。
5. `POST /api/auth/logout`，JSON `{}`，清除该浏览器会话和未完成的授权状态，返回 `{ok:true,authenticated:false,profile:null}`。

所有普通 API 请求继续检查 Host、Origin 和跨站请求。OAuth 回调允许跨站顶层 GET 导航，但仍要求受信 Host 和 state 与浏览器匹配。没有实现模拟成功或备用虚拟账户。

## 环境配置

配置只从进程环境读取。[.env.example](../.env.example) 只有空占位，不会自动加载。不要把真实 AppSecret、私钥、访问令牌写入仓库、前端、截图、终端输出或提交记录。修改环境后需要重启后端。

| 环境变量 | 内容 |
|---|---|
| `WECHAT_APP_ID` | 微信开放平台审核通过的网站应用 AppID |
| `WECHAT_SECRET` | 对应网站应用 AppSecret |
| `WECHAT_REDIRECT_URI` | 已登记 HTTPS 站点的 `/auth/callback/wechat` 完整地址 |
| `ALIPAY_APP_ID` | 支付宝开放平台应用 AppID |
| `ALIPAY_PRIVATE_KEY` | 应用 RSA2 私钥，至少 2048 位 |
| `ALIPAY_PUBLIC_KEY` | 开放平台提供的支付宝 RSA2 公钥，不能误填应用公钥 |
| `ALIPAY_REDIRECT_URI` | 已登记 HTTPS 站点的 `/auth/callback/alipay` 完整地址 |

支付宝密钥支持完整 PEM 或 Base64 DER；PEM 可包含真实换行或字面量 `\n`。当前实现为普通公钥模式，没有实现支付宝证书模式，不能把证书文件当作公钥填写。支付宝需要可选 `cryptography` 库，依赖列于 [requirements-auth.txt](../requirements-auth.txt)；缺失时仅禁用支付宝，不会自动安装，也不会阻塞微信或本地 OCP/MCP 服务。

默认本地模式只绑定 `127.0.0.1`。localhost、127.0.0.1 和其他本地地址不是这里接受的真实 OAuth 回调域名；本地访问与公网回调跨域时，浏览器绑定 Cookie 不会跟过去，因此不会伪装成可登录。仓库另提供可选云模式与容器配置，启用时需要配置受信任的 HTTPS 站点；本次尚未连接云账号或部署公网，也没有真实账号联调结果。公网注册、平台审核、HTTPS 部署及真实账号测试仍需完成。HTTPS 反向代理必须保留受信 Host，后端不会依据任意 `X-Forwarded-*` 头自动放宽来源。

## 平台实现与资料来源

微信使用网站应用登录 `qrconnect`、`response_type=code`、`scope=snsapi_login`，服务端通过 `/sns/oauth2/access_token` 交换授权码，再通过 `/sns/userinfo` 读取 `nickname` 与 `headimgurl`。这条流程属于微信开放平台网站应用，不是公众号 `snsapi_userinfo` 网页授权。[微信官方网站应用登录指南](https://developers.weixin.qq.com/doc/oplatform/Website_App/WeChat_Login/Wechat_Login.html)及[授权关系接口指南](https://developers.weixin.qq.com/doc/oplatform/Website_App/WeChat_Login/Authorized_Interface_Calling_UnionID.html)。

支付宝使用公共网页授权地址 `https://openauth.alipay.com/oauth2/publicAppAuthorize.htm` 与 `scope=auth_user`，再调用 `alipay.system.oauth.token` 和 `alipay.user.info.share` 读取 `nick_name`、`avatar`。应用还需拥有相应用户授权产品权限；`auth_base` 不能替代昵称头像授权。[支付宝访问令牌接口](https://iopenhome.alipay.com/docs/ac/solution_api/oauth_token)、[用户信息接口](https://iopenhome.alipay.com/docs/ac/solution_api/infoshare)及[官方 Python SDK](https://github.com/alipay/alipay-sdk-python-all/blob/master/alipay/aop/api/DefaultAlipayClient.py)。

支付宝权限与 scope 必须以具体应用当前开通的产品为准。当前实现选择公共网页流程中的 `auth_user`；若该应用的现行平台指引要求 `auth_user_info` 或其他产品接口，需要按该指引调整并重新联调。当前没有应用配置，不能认定该 scope 已获授权或已经可用。

支付宝请求使用标准 RSA2：对非空参数按键名排序，以未 URL 编码的 `key=value` 拼接后进行 SHA-256 / RSA PKCS#1 v1.5 签名。响应使用支付宝公钥对原始响应对象 JSON 字节验签，保留原来的空格与转义；无签名、签名不符或用户标识核对失败均不建立会话。

## 会话与验收边界

state 为安全随机值，保留十分钟、绑定当前浏览器，网络交换前即消费，不能重放。登录成功会轮换随机会话 ID，八小时后失效。Cookie 为仅当前主机、`Path=/`、`HttpOnly`、`SameSite=Lax`；真实 HTTPS 登录额外设置 `Secure`。会话和 state 只存内存，服务重启后失效。平台 OAuth 令牌只用于后端临时读取资料，不返回前端，也不长期保存；会话只保存最小昵称、头像、来源及内部身份摘要。

此登录提供商城身份与头像，不授予瑞幸订单权限，也不替代瑞幸官方 Token。默认本地模式仍使用单机 MCP 连接；可选云模式另通过安全的浏览器 Cookie 隔离各会话的瑞幸连接、凭证与结果。云模式相关代码测试不能替代真实线上部署验收；前端还需接入云模式写请求要求的稳定 `idempotencyKey`，并完成平台账号与支付流程联调。

`tests/test_auth.py` 使用模拟微信响应、临时生成的 RSA 密钥和本地 HTTP 服务，验证 Cookie/state 绑定、过期与重放、响应验签、失败时无会话、头像读取及注销。未向真实账号请求授权，也未生成真实用户会话。真实验收还需分别完成平台审批、配置回调、用户授权、头像显示、注销和会话过期检查。
