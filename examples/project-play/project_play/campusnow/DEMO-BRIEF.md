`state.plan.group_options` 非 null 且 `phase==='PLAN_AWAIT_CONFIRM'` 时,在商品决策区上方渲染方案卡:

```
┌─────────────────┐ ┌─────────────────┐ ┌─────────────────┐
│ A · 经济款        │ │ B · 人气款 ⭐     │ │ C · 满配款        │
│ ¥52.8 余¥47.2    │ │ ¥59.4 余¥40.6    │ │ ¥69.3 余¥30.7    │
│ 小黄油拿铁×3      │ │ 生椰拿铁×2 …     │ │ …               │
│ ☕×4 🍵×2 🔥1杯热 │ │ ☕×4 🍵×2 🔥1杯热 │ │ ☕×4 🍵×2 🔥1杯热 │
│   [选这套]       │ │   [选这套]       │ │   [选这套]       │
└─────────────────┘ └─────────────────┘ └─────────────────┘
```

- 点击 → `POST /api/choose-plan {option_id:"B"}`;返回后 `group_options` 变 null,下方渲染所选方案明细(现有 product 卡复用)
- 每行 line 的图标:`hot→🔥`,`noncoffee→🍵`(note 字段有中文说明)
- 菜单来源徽标:`plan.menu_source==='real-mcp'` → 绿标「🟢 瑞幸实时菜单」;否则黄标「⚠️ 本地降级数据」

### P0-2 真实支付区(二维码弹窗)——路演高潮

`order.real === true` 且 `phase==='ORDER_AWAIT_PAY'` 时,订单区的支付按钮替换为:

```
┌──────────────────────────────┐
│   微信扫码支付 ¥59.40          │
│   ┌────────┐                 │
│   │ QR img │  ← <img src={order.pay_qr_url}> (PNG 直载)
│   └────────┘                 │
│   瑞幸单号 7695313…           │
│   状态:待付款(自动检测中…)     │
│  [我已支付,立即检测] [撤单]     │
└──────────────────────────────┘
```

- `order.pay_qr_url` 是可直接加载的二维码 PNG,`<img>` 即可,尺寸 ≥200px
- 状态行实时显示 `order.pay_status_name`(轮询 state 已有,别加新轮询)
- 「立即检测」→ `POST /api/check-payment`;「撤单」→ 确认弹窗(modal)后 `POST /api/cancel-order`,提示"未支付撤单零费用"
- **支付到账是后端自动检测**:phase 会自动跳到 INVOICE_AWAIT_CONFIRM,给个 toast「✅ 支付已确认,瑞幸已接单」

## 联调自测清单(改完逐条过)

1. `bun run start`(后端真实模式),打开 `localhost:4420`
2. 贴团购话术 → 三张方案卡出现,来源徽标绿色
3. 选 B → 明细切换 → 确认弹窗 → **真实订单创建,二维码显示**
4. 不扫码等 3 秒 → 状态仍「待付款」;点「撤单」→ 确认 → 提示零费用,任务结束
5. 重来一遍,这次扫码付款(约 ¥59)→ 3 秒内自动跳开票环节 → 确认 → ARCHIVED
6. 归档区 4 个文件标签正确;preview 收据显示「本地模拟收据·非商家开具」
7. `POST /api/reset` 后跑旧剧本(电子配件)→ 全程「模拟」标签不受影响
8. e2e 不用跑(后端无改动);但确保 UI 在 `start:mock` 下也不报错(order.real 为 undefined)

## 边界提醒

- 不要在前端写死任何"已支付"判断,一切以后端 phase/pay_status_name 为准
- 不要缓存二维码 URL,每次 state 都取 `order.pay_qr_url`
- 真实订单重复确认可能创建多单:确认按钮点击后立即禁用(busy 机制已有)
